# API entities

## `/couriers`

Используется для получения справочника курьеров.

| Поле API | Назначение            |
| -------- | --------------------- |
| `_id`    | идентификатор курьера |
| `name`   | имя курьера           |

## `/deliveries`

Используется для получения информации о доставках, курьерах, оценках и чаевых.

| Поле API      | Назначение             |
| ------------- | ---------------------- |
| `order_id`    | идентификатор заказа   |
| `order_ts`    | дата и время заказа    |
| `delivery_id` | идентификатор доставки |
| `courier_id`  | идентификатор курьера  |
| `address`     | адрес доставки         |
| `delivery_ts` | дата и время доставки  |
| `rate`        | оценка доставки        |
| `tip_sum`     | сумма чаевых           |
| `sum`         | сумма заказа           |

Для витрины используются `order_id`, `order_ts`, `delivery_id`, `courier_id`, `rate` и `tip_sum`.

Поле `sum` из `/deliveries` не используется, так как сумма заказа уже есть в данных order subsystem.

`address` и `delivery_ts` для расчёта витрины не требуются.

## Существующие данные DDS

Для расчёта витрины используются существующие таблицы DDS:

### `dds.dm_orders`

Используемые поля:

* `id` — идентификатор заказа в DDS;
* `order_key` — идентификатор заказа из источника;
* `order_status` — статус заказа;
* `restaurant_id` — ресторан;
* `timestamp_id` — ссылка на дату и время заказа;
* `user_id` — пользователь.

В текущей таблице нет информации о курьере. Для связи заказа с доставкой потребуется дополнить модель.

### `dds.dm_timestamps`

Используемые поля:

* `id` — идентификатор записи;
* `date` — дата заказа.

Дата заказа используется для определения расчётного года и месяца. Дата доставки для этого не используется.

### `dds.fct_product_sales`

Используемые поля:

* `order_id` — ссылка на заказ;
* `total_sum` — сумма позиции заказа.

`total_sum` используется для расчёта общей суммы заказов.

## Что необходимо добавить в DDS

Для данных из delivery subsystem необходимо сохранить:

* курьера и его имя;
* связь доставки с заказом;
* связь доставки с курьером;
* оценку доставки;
* сумму чаевых.

Также существующую модель `dds.dm_orders` необходимо дополнить связью с курьером/доставкой.

Конкретная структура новых таблиц и связей определяется на этапе проектирования DDS.

## Получение данных из API

Для `/couriers` и `/deliveries` используется пагинация через параметры `limit` и `offset`.

При загрузке `/deliveries` необходимо задавать стабильную сортировку. В ходе проверки API использовалась сортировка по `delivery_id`.

Для отбора периода используются параметры:

* `from` — начало периода, включительно;
* `to` — конец периода, не включая указанное значение.

По заданию данные должны загружаться за предыдущие 7 дней.
